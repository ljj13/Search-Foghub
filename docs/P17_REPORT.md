## 修改位置

只改了 `src/styles/layout.css` 里的 `.home-content` 与 `src/styles/responsive.css` 里两处同名的响应式覆盖，没有动任何子元素、没有加负 margin、没有新增定位：

- `.home-content` 是问候语、时间、日期、搜索框、快捷方式/文件夹和「整理捷径」的共同父容器，本来靠 `margin:auto` 在视口里垂直居中。
- 给它的底部内边距加 60px（`112px → 172px`）：居中的盒子整体变高 60px，于是内容组的顶边恰好上移 **30px**，组内元素之间的间距一个像素都没变。
- `@media (min-height:641px) and (max-height:820px)` 的短屏分支同步 `84px → 144px`（同样 30px 上移，覆盖 1440×760、1024×768 等）。
- `@media (max-width:600px)` 的手机分支 `90px → 114px`，只上移 **12px**，避免小屏内容顶到顶栏。

背景图、遮罩、左上角 Logo、右上角按钮和页脚都没有改动；搜索、快捷方式、文件夹、设置等交互未触及。

## 上移距离与实测

在本地 7 个视口先测基线、改完再测一次，线上发布后再用真实浏览器复测（数值为元素 `getBoundingClientRect().top`，单位 px）：

| 视口 | 时钟（改前 → 改后） | 位移 | 页面纵向溢出 |
| --- | --- | --- | --- |
| 1920×1080 | 298 → 268 | −30 | 0 |
| 1440×900 | 208 → 178 | −30 | 0 |
| 1440×760 | 172 → 142 | −30 | 0 |
| 1024×768 | 191 → 161 | −30 | 0 |
| 768×1024 | 299 → 269 | −30 | 0 |
| 390×844 | 178 → 166 | −12 | 0 |
| 360×800 | 171 → 141 | −30 | 0 |

问候语、搜索框、快捷方式区、「整理捷径」的位移与时钟完全一致（例如 1440×900：搜索 464 → 434，快捷方式 565 → 535，整理捷径 694 → 664），说明是整组移动。

线上复测（`/assets/index-E6TCeYEM.css`）：1440×900 时钟 178、搜索 434、快捷方式 535、整理捷径 664；1440×760 为 142/354/439/568；768×1024 为 269/467/568/697；390×844 为 166/359/443/653；四档均无纵向滚动、控制台 0 报错。
